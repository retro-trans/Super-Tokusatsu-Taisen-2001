# Episode 6 crash report (2026-10-09)

The user relayed a crash after the reward box at the end of the chapter featuring Colonel Zol's death. The reporter's build is unknown and no save is available. A matching crash is reproducible in the published v0.3.6 image. The existing v0.3.17 repair, included in public v0.3.18, fixes this fault; no new game image or release was made for this investigation.

The affected chapter is title ID 7, `Onslaught! Shocker Japan`. On the route that skips the optional Boy & Robo chapter it is displayed as Episode 6. When Intermission draws the stage-clear footer, the old English caption requires 68 bytes including its terminator. Its native caller allocates only 56 bytes for the string, so the caption overwrites the saved return address with `0x01770179` and execution attempts to return to unmapped memory. The earlier five chapter titles fit their buffers and return normally. This matches the reported point of failure; texture replacement does not cause this memory overwrite.

The caller starts at `0x80070D14`, with its stack allocation at `0x80070D1C`. In the old build, the frame is 0x58 bytes, text begins at SP+0x18 and the saved return address is at SP+0x50. The v0.3.17 patch in `tools/intermission_layout.py` expands the frame to 0xA8 and moves the saved return address to SP+0xA0, leaving 136 bytes for the caption. It also repairs the Stage prefix and limits long captions to the `Clr.` suffix. The corrected Episode 6 caption requires 66 bytes and returns safely.

`tools/check_stage_clear_crash.py` reproduces the old invalid return and executes the completed v0.3.18 disc's native caller, composer and string-copy routines for all 91 title IDs with every number from 0 through 90 (8,281 cases). All captions return safely, preserve callee-saved registers and the parent stack guard, and fit both the buffer and footer width. Maximum caption size is 72 bytes and maximum advance is 284 pixels. Both live database copies agree. Graphics submission is modeled; this is not a complete chapter playthrough in an emulator or on hardware.

Run `C:/Python/python.exe tools/check_stage_clear_crash.py` for a dry run, then add `--verify` to save the report to `work/output/STT2001_EN_v0.3.18_stage_clear_crash_verification.json`. The checked disc SHA-256 is `a002b82cc05c7184e3bb5cfac0d0e43ea41a7875ccfc82b2e110446dbc73df7a`.

Suggested response to the reporter: update to [v0.3.18](https://github.com/retro-trans/Super-Tokusatsu-Taisen-2001/releases/tag/v0.3.18), using the v0.3.6-to-v0.3.18 upgrade patch if applicable, and install its matching texture package. Start the updated disc afresh and load an in-game memory-card save: an emulator save state may retain the old executable in RAM. If the reporter already uses a freshly started v0.3.18 image, treat that as a separate unresolved crash and request their build details and save when available.
