# Font gradient and shadow

## v0.9.4: flat fill and aligned letter bodies

The user approved the shadow and requested removing the gradient. The current
style uses the source antialias levels uniformly at every row, retaining the
same shadow and private palettes. The native renderer itself is unchanged.

`tools/font_metrics.py` uses source-raster guides: capital top 8, lowercase
body top 18, baseline 45 and descender bottom 49 (four source pixels per
native pixel). The copied a/p/q bodies started at 16 while e and most short
lowercase bodies started at 18; their body bands now share the latter guide.
The f ascender and J bottom are aligned without cutting off their curves.
Digits retain their solid contours, with only outlying antialias fringes
trimmed. Accented fallback Latin letters keep their marks while their bodies
share the Latin baseline; the ellipsis sits with the existing period.
Ascenders, dots, accents and descenders intentionally retain different heights.
Character advances and public save-name token IDs remain unchanged.

## v0.9.3: historical gradient treatment

Local v0.9.3 adapts the vertical fill and down-right one-pixel shadow used by
`../Getter Robo Daikessen/tools/font.py`. The current Skies/Rayblade source
font remains the glyph source; this change adds shading, not a new typeface.

The native 2x atlas has four levels: transparent, dark shadow, lower ink and
upper ink. White, red, cyan, yellow and disabled text retain their own colours.
Five private palettes occupy previously empty CLUT rows 10–14 in 17 of the
18 existing font copies. The encyclopedia tab atlas (BATTLE537) retains its
separate artwork palettes; English drawing selects the shared main text CLUT.
Original palette rows 0–9 and row 15 remain unchanged,
so weapon badges and other native graphics keep their previous colours.

The renderer maps the five original colour roles to those palettes. Unused
colour roles produce no English packets. The same opaque FT4 packets, object
pool, glyph advances, clipping, VRAM extent and heap boundary are retained.
The modified routine still ends at `0x800DDFF0`, before the reserved Defend
label. Three reclaimed instructions cover the palette mapping and bounds
check; the reordered loads retain the PS1's independent load-delay slots.

The source glyph's existing left bearing makes room for the shadow without
changing its advance or clipping source ink. A mark with less bearing keeps
its source ink; only the trailing shadow is clipped to its existing rectangle.
The user explicitly requested native rendering without texture replacements.
The game patch supplies the complete effect. Builds from v0.9.3 skip automatic
texture exports; the historical exporter remains available explicitly through
`--texpack`, but is not required or delivered for this native font update.
Movie subtitles, audio, gameplay and translation text are unchanged from
local v0.9.2.

The styled compressed font copy adds one 2,048-byte archive sector. The existing
disc repacker updates later archive directory entries and takes that sector
from trailing padding. Disc length and fixed boot/movie/XA allocations stay
unchanged; relocated sound and attack archives retain identical payloads.

The public v0.9.7 release additionally includes an optional exact-native
compatibility package, generated by `tools/native_font_pack.py`. This is a
release-instruction attachment, not the implementation of the effect. It
samples the finished font pages and CLUTs and repeats each native pixel at
4x size, preserving the flat ink, shadows and icon colours. It does not use
the historical glyph-redrawing exporter and does not replace the new title
artwork. The native game remains the recommended way to view the update;
disable old replacement packs when testing. The compatibility ZIP is not
installed or enabled automatically.
